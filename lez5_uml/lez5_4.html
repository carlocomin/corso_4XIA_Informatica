Attributi: nome, tipo e significato

Un attributo deve rappresentare una proprietà utile per il problema, non una parola incontrata nel testo.

← PrecedenteSuccessiva →

La forma essenziale

- livello: Integer = 0

Leggiamo: attributo privato chiamato livello, di tipo intero, con valore iniziale 0. La forma che useremo è visibilità nome: Tipo; il valore iniziale si aggiunge soltanto quando serve.

Nei nostri esempi usiamo attributi per dati semplici, come un codice, una descrizione o una quantità. Non è un limite di UML. Se dobbiamo rappresentare un’entità con proprie proprietà e relazioni, valutiamo una classe separata.

I tipi UML non sono parole chiave C++

Nel modelloSignificatoEsempio di traduzione C++
IntegerNumero interoint
RealNumero realedouble, con precisione finita
BooleanVero o falsobool
StringTestostring

È una corrispondenza didattica, non un’identità perfetta: int ha limiti di rappresentazione. Possiamo anche usare tipi definiti nel progetto, purché ne chiariamo il significato.

Le regole vanno espresse

Il tipo Integer non basta a dire che il livello deve essere fra 0 e 100. Aggiungiamo il vincolo {0 <= livello e livello <= 100}, con una nota o una frase accanto al diagramma. Non serve introdurre un nuovo linguaggio formale per scrivere questa regola.

Checkpoint

Per memorizzare il nome di uno studente serve necessariamente una classe Nome?

Mostra rispostaNascondi risposta

No. Nel nostro modello il nome può essere un attributo nome: String. Una classe separata avrebbe senso soltanto se il problema richiedesse di trattarlo come un’entità con una propria struttura o responsabilità.
