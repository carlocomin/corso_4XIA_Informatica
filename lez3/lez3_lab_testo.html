Laboratorio guidato · File I/O · 8/19

Il registro delle consegne del robot

Primo laboratorio sui file di testo: scriviamo e rileggiamo token separati da spazi, un passo alla volta. Circa 2 ore per il percorso base; sfide aggiuntive facoltative.

← Precedente Successiva →

Un robot, un file, un piccolo rapporto

Un robot porta pacchi in alcune zone della scuola. Per ogni tappa registriamo la destinazione e il numero di pacchi. Il primo programma salva il registro; un secondo programma lo rilegge e produce un riepilogo.

Obiettivo: capire da dove arriva il dato e dove va. Procedi una fase alla volta: prima prevedi il risultato, poi esegui, infine controlla il file con un editor.

Il formato: soltanto token separati da spazi

Un token è un elemento che leggiamo separatamente. Ogni consegna occupa due token, sempre nell’ordine destinazione pacchi. Questa coppia è un record, cioè i dati di una consegna. La destinazione è una sola parola; il numero di pacchi è un intero da 0 a 20. Nel programma finale accettiamo al massimo 20 tappe.

ingresso 3 significa “3 pacchi all’ingresso”; la coppia successiva è laboratorio 5. Non aggiungere titoli, conteggi iniziali, virgole o punti e virgola al file.

Per questa attività: niente CSV, file binari, struct, vector, menu o lettura di righe con getline. Non servono nemmeno array: possiamo elaborare una coppia alla volta. In C++ useremo ofstream, ifstream, << e >>.
Fase 0 · Preparazione · 10 minuti

Prepara due programmi separati

  1. Crea una cartella di lavoro per il laboratorio. Scarica gli scheletri sotto oppure ricostruiscili nel tuo IDE.
  2. scrivi_consegne.cpp contiene il programma che scrive; leggi_consegne.cpp contiene quello che legge.
  3. Compilali come due programmi distinti: non inserire due main nello stesso progetto eseguibile.
  4. Imposta per entrambi la stessa cartella di lavoro, cioè quella da cui il programma cerca i percorsi relativi. Non è necessariamente la cartella del sorgente o dell’eseguibile.
  • Scarica lo scheletro dello scrittore
  • Scarica lo scheletro del lettore
  • Scarica il file dati di riferimento, da usare per confrontare il risultato, non per saltare la scrittura.

Fase 1 · Scrittura · 20 minuti

Dal programma al file

Lo scheletro scrive già la prima coppia. Eseguilo una volta e apri consegne.txt con un editor. Poi completa il TODO aggiungendo le altre quattro coppie del dataset, con un singolo spazio tra un token e il successivo.

  1. ofstream out("consegne.txt") apre il file per scrivere. if (!out) controlla che l’apertura sia riuscita.
  2. out << ... invia testo al file, non allo schermo. ' ' è il carattere spazio che separa i token.
  3. close() conclude la scrittura; il controllo successivo serve a non ignorare errori finali.

Controllo pratico: confronta il file prodotto con il dataset. Esegui lo scrittore una seconda volta: le cinque coppie devono restare cinque, non diventare dieci.

Mostra soluzioneNascondi soluzione
Attenzione: questa apertura crea il file se manca, ma cancella il contenuto precedente se esiste. In questa fase è voluto. Non usare lo scrittore per provare a leggere un file modificato: lo riscriverebbe da capo.
Fase 2 · Prima lettura · 15 minuti

Dal file a due variabili

Salva eventuali modifiche a consegne.txt, esegui il lettore e osserva le variabili destinazione e pacchi. Per ora vogliamo leggere soltanto la prima coppia.

Prima di eseguire: scrivi l’output che ti aspetti. Spiega perché questa prova non stampa anche laboratorio, biblioteca e le altre destinazioni.

Mostra rispostaNascondi risposta

L’output è ingresso: 3 pacchi. La lettura in >> destinazione >> pacchi è eseguita una sola volta. Il resto del file non viene elaborato: serve un ciclo.

Confronto con la tastiera: cin >> pacchi legge dalla tastiera; in >> pacchi legge dal file aperto. Non devi digitare le consegne durante la lettura. Lo stream di input si chiude automaticamente alla fine del programma.
Fase 3 · Ripetere la lettura · 25 minuti

Una coppia alla volta, fino alla fine

Nel lettore sostituisci il blocco di lettura singola, dalla dichiarazione di destinazione fino alla stampa, con lo schema seguente. Completa il TODO: per ogni coppia letta correttamente, stampa destinazione e pacchi.

  1. La condizione del while prova a leggere una destinazione. Se il file è finito regolarmente, il ciclo termina.
  2. Se una destinazione è stata letta, deve seguirla il numero di pacchi: se manca o non è leggibile, segnaliamo un errore.
  3. Solo dopo il successo di entrambe le letture possiamo stampare o elaborare la coppia. Non usare while (!in.eof()).

Fermati e ragiona

Per leggere cinque consegne servono cinque righe nel file?

Prevedi che cosa cambia se sostituisci alcuni spazi con ritorni a capo oppure aggiungi più spazi tra i token.

Mostra rispostaNascondi risposta

Con >> non cambia il risultato: spazi, tabulazioni e ritorni a capo separano i token. Il record è una coppia di valori, non necessariamente una riga. Nel file base scriviamo un singolo spazio per avere una convenzione semplice e uniforme.

Fase 4 · Elaborare e riscrivere · 30 minuti

Quante tappe? Quanti pacchi? Quale media?

Estendi il lettore con un conteggio e un accumulatore. Poi salva il risultato in un secondo file, riepilogo.txt. Non sovrascrivere consegne.txt, che rimane il nostro input.

  1. Prima del ciclo inizializza a zero tappe e totale.
  2. Nel corpo, dopo i controlli, incrementa tappe e aggiungi pacchi al totale. Rifiuta una ventunesima consegna prima di contarla.
  3. Dopo il ciclo verifica che la lettura sia finita senza errori. Solo allora apri il file di riepilogo con un nuovo ofstream.
  4. Scrivi sei token separati da spazi: tappe, il conteggio, pacchi, il totale, media, la media.
  5. Per la media usa static_cast<double>(totale) / tappe. Se il file era vuoto, non dividere per zero: scrivi il token ND al posto della media.
  6. Chiudi il file di output e controlla l’esito, come nello scrittore.

Non aggiungere un menu. Il programma legge il file già esistente, stampa le coppie e produce il riepilogo. Nei token numerici usa soltanto interi separati correttamente: non valori attaccati a testo, come 3abc.

Prima di aprire la soluzione: calcola su carta conteggio, totale e media del dataset base. Prevedi anche i sei token del riepilogo per un file vuoto.

Mostra soluzioneNascondi soluzione

Dataset base: tappe 5 pacchi 15 media 3. File vuoto: tappe 0 pacchi 0 media ND.

Segui tre blocchi: apertura; ciclo con conteggio e somma; scrittura del risultato. Il riepilogo viene creato solo dopo la lettura corretta. Le eventuali righe già mostrate a schermo prima di un errore non sono un riepilogo finale.

Fase 5 · Collaudo e consegna · 20 minuti

Un test alla volta, senza riscrivere l’input per errore

Conserva una copia del file corretto. Prima di ogni test modifica solo consegne.txt, poi esegui il lettore completo. Non rilanciare lo scrittore, altrimenti cancelleresti la modifica da verificare.

  1. Usa il dataset base e controlla il riepilogo calcolato nella fase 4.
  2. Lascia soltanto ingresso 3, senza ritorno a capo finale.
  3. Svuota il contenuto del file, senza eliminarlo.
  4. Ripristina i dati e sostituisci un numero con la parola due.
  5. Ripristina i dati e lascia l’ultima destinazione palestra senza il numero di pacchi.
  6. Prova ingresso -1, poi ingresso 21. Infine rinomina temporaneamente il file per simulare un input assente.
Mostra risultati attesiNascondi risultati attesi
  • Dataset base: cinque coppie; tappe 5 pacchi 15 media 3.
  • Una coppia senza fine riga: successo; tappe 1 pacchi 3 media 3.
  • File vuoto: successo; tappe 0 pacchi 0 media ND.
  • Numero sostituito con due o ultimo numero mancante: errore di lettura, senza un nuovo riepilogo.
  • −1 o 21 pacchi: dato fuori intervallo, senza un nuovo riepilogo.
  • File assente: errore di apertura, senza un nuovo riepilogo.

Come prova aggiuntiva, un file di 20 coppie valide è ammesso; la ventunesima deve essere rifiutata.

Non farti ingannare da un vecchio risultato: se l’input è errato, il programma non riscrive riepilogo.txt. Un riepilogo precedente potrebbe quindi essere ancora presente. Prima di un test negativo rinominalo, oppure controlla il messaggio e la data dell’ultima modifica.

Da consegnare: i due sorgenti completati, il file dati base, il riepilogo corretto e una breve nota sui test eseguiti. Devi saper indicare nel codice dove apri, leggi, scrivi, controlli e concludi le operazioni.

Sfida facoltativa A · 15–20 minuti

Aggiungi una consegna senza cancellare le altre

Riparti dal file base con cinque coppie. Crea un terzo programma separato, aggiungi_consegna.cpp, che apra il file con ios::app e aggiunga aula4 6. Metti uno spazio prima della nuova destinazione: l’ultimo token precedente potrebbe non essere seguito da uno spazio.

Esegui l’aggiunta una sola volta, poi rilancia soltanto il lettore. Prevedi il nuovo conteggio, il totale e la media. Che cosa accadrebbe rilanciando invece lo scrittore iniziale?

Mostra soluzioneNascondi soluzione

Il lettore produce tappe 6 pacchi 21 media 3.5. Il cast evita la divisione intera 21 / 6 = 3. Lo scrittore iniziale ripristinerebbe le sole cinque consegne base. Ogni esecuzione del programma di aggiunta inserisce un’altra coppia: non cancella e non evita duplicati.

Sfida facoltativa B · 15–20 minuti

Qual è la consegna più grande?

Nel lettore trova la destinazione della singola consegna con il maggior numero di pacchi, senza memorizzare tutte le coppie in un array. Non devi sommare record con lo stesso nome. In caso di parità conserva la prima. Con file vuoto stampa Nessuna destinazione.
