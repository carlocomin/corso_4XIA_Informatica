File di testo a spazi

Leggiamo tre token con >>; scriviamo i tre campi con <<. Il nome, in questo formato, è una sola parola.

Tre campi letti direttamente con >>

Ogni studente occupa tre token nell’ordine matricola nome anno. Non c’è intestazione e il nome è una sola parola. Spazi, tabulazioni e fine riga separano i token.

Caricare: una struct alla volta

  1. Apriamo il file e poniamo n = 0.
  2. Il ciclo legge la matricola; dentro leggiamo nome e anno.
  3. aggiungiStudente controlla i valori, i duplicati e lo spazio disponibile, poi inserisce il record.

Un file vuoto carica zero studenti. La fine regolare del file non è un errore; un record iniziato ma incompleto lo è.

Scelta semplice: carichiamo direttamente nell’array, senza copie temporanee. Se il caricamento restituisce false, l’array può essere parziale: il programma dimostrativo si ferma e non continua a elaborarlo.

Salvare: un ciclo sull’array

Scriviamo soltanto gli elementi da 0 a n - 1. Per usare questo formato i nomi devono essere singole parole: la funzione non controlla né corregge nomi con spazi.

Il file di uscita viene riscritto, non accodato: così conserva anche modifiche e rimozioni. Dopo close(), !out.fail() comunica se la scrittura è riuscita.

Checkpoint

Il file termina con 1004 Edsger, senza anno. Possiamo continuare a elaborare l’array?

No. La lettura dell’anno fallisce e il caricamento restituisce false. Il chiamante deve fermarsi: non assumiamo che l’array contenga un archivio completo.

Dall’array alla riga

L’array contiene {1002, "Turing", 5} e {1003, "Grace", 3}, con n = 2. Quali righe scriviamo?
