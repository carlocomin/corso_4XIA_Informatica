const e constexpr

Entrambe impediscono di modificare una variabile, ma constexpr aggiunge una garanzia: il valore deve essere determinabile durante la compilazione.

← Precedente Successiva →

Due promesse diverse

const promette: dopo l’inizializzazione non cambierò questo oggetto. Il valore iniziale può però arrivare mentre il programma è in esecuzione.

constexpr promette: questo valore è una costante calcolabile dal compilatore. Una variabile constexpr è automaticamente anche const.

Runtime

const

Protegge un valore da modifiche successive. Non garantisce, da solo, che quel valore sia noto a compile time.

Compile time

constexpr

Richiede un’inizializzazione valutabile dal compilatore e rende esplicito che il valore può essere usato dove serve una costante.

Relazione da ricordare: ogni variabile constexpr è const; non ogni variabile const è una costante valutabile a compile time.

Perché useremo constexpr int N = 5;

La dimensione di un array statico deve essere una costante intera nota durante la compilazione. Anche alcuni const int possono soddisfare questo requisito, ma constexpr lo dichiara e lo fa controllare esplicitamente dal compilatore.

Checkpoint

Quali dichiarazioni sono valide?

Dopo aver letto n da input, valuta:

  • const int a = n;
  • constexpr int b = 10;
  • constexpr int c = n;
Mostra risposta Nascondi risposta

Le prime due dichiarazioni sono valide. a non cambierà, ma nasce a runtime; b è noto a compile time. La terza non è valida, perché il compilatore non conosce il valore letto in n.

Attività lampo · 3 minuti

Scegli la promessa corretta

Per ciascun caso scegli const o constexpr: numero di giorni della settimana; voto letto da tastiera che non deve più cambiare; capacità fissa di un array; risultato ricevuto da una funzione durante l’esecuzione.
